# AI Rewrite Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付五个可以分别安装和调用的通用重写 skills，验证后上传到用户授权的新建公开 GitHub 仓库。

**Architecture:** 每个技能自带 SKILL.md、UI 元数据和必要的本地参考文件，不依赖其他技能目录。根 README 说明选用和组合方法，docs/methodology.md 记录来源与适配差异。

**Tech Stack:** Markdown、YAML、Git、GitHub CLI；已有 Python 环境仅用于格式和引用验证，不给技能增加运行时依赖。

**Spec:** `docs/design.md`（用户于 2026-09-30 确认，含第一步的五项交付物与三类行为要求）。

## Global Constraints

- 多个独立技能，不设必须执行的总控入口，不绑定项目、行业、架构、语言、模型或测试框架。
- 蒸馏交付 PRD、功能清单、外部接口约定、状态与恢复规则、功能到 E2E 的对应表。
- 每条结论可追溯；证据不足显式待确认，不由 AI 补成需求。
- 行为分为“确认保留”“确认调整”“尚待确认”；已有明确依据不重复索要确认。
- 保留既有测试中的业务断言；E2E 对应、实际覆盖和运行通过分别记录。
- 正文以中文为主，技能目录使用已确定的英文名称；每个技能均能单独复制安装。
- 只上传通用内容；不上传聊天记录、私有项目材料、凭据、评测临时输出或本机路径。

## Review Focus

1. 协议、代码和测试互相矛盾时，不擅自选择目标需求；Task 1 用冲突材料验证。
2. 已知缺陷不自动等于批准改变兼容行为；Task 1、3 区分已批准变更与未决项。
3. 外部规格不采用本仓库模板时仍能独立使用；Task 2 使用自然语言规格和既有测试验证。
4. 测试通过却发生外部副作用或证据缺失时，不直接判定可发布；Task 4 使用虚构回放记录验证。
5. 负载、版本、样本不同造成的指标改善，不能算已证实优化；Task 5 用不等价基线验证。

**Interfaces:** 接受旧系统资料和提取范围；输出五项逻辑交付物及共享证据/行为记录。下游按内容读取，不要求特定文件名。

- [x] 用包含协议与代码冲突、已批准变更、缺失运行证据的中性材料进行无技能基线试用，保存实际结果到仓库外工作目录。
- [x] 编写入口与交付物模板：结论编号、来源/版本/定位、三类标记、确认依据、验收与 E2E、未知及影响范围。
- [x] 独立代理仅凭该技能和原始材料产出交接包；检查五项齐备、冲突保留、未编造需求与通过记录。
- [x] 验证前置信息、引用与 UI 元数据；根据实际问题修订并提交该技能。

## Task 2：依据规格重写技能

**Files:** `skills/spec-driven-rewrite/SKILL.md`、`agents/openai.yaml`、`references/handoff.md`。

**Interfaces:** 接受任意来源的规格、目标约束、测试入口和范围；输出实现及规格映射、运行证据与未决事项。

- [x] 基线场景：自然语言规格包含保留、批准调整及未决行为，已有测试与其中一项旧行为冲突。
- [x] 编写规格校验、新上下文实现、并行任务边界、缺口回流、现有测试迁移及交付记录。
- [x] 独立试用检查：不强迫重跑蒸馏，不放宽测试预期，不猜测未决行为，只阻塞相关范围。
- [x] 验证并提交该技能。

## Task 3：差异与质量审计技能

**Files:** `skills/rewrite-parity-audit/SKILL.md`、`agents/openai.yaml`、`references/audit-report.md`。

**Interfaces:** 接受新版本和预期行为依据；新旧对比需要旧版本证据。输出独立的行为差异、缺陷/安全判断及修复复审记录。

- [x] 基线场景：一个批准的行为改变、一个真实回归、一个沿袭旧版的缺陷、一个未决规则。
- [x] 编写证据等级、两类审计结论、按模块分工、实施者修复与新上下文复审流程。
- [x] 独立试用检查：不将批准变化误报回归，不把继承旧缺陷判为安全，不把猜测说成已复现。
- [x] 验证并提交该技能。

## Task 4：发布验证技能

**Files:** `skills/rewrite-release-validation/SKILL.md`、`agents/openai.yaml`、`references/release-record.md`。

**Interfaces:** 接受候选版本、目标环境、验收标准与测试；输出满足条件/不满足条件/证据不足，以及适用的彩排、切换和回退记录。

- [x] 基线场景：E2E 摘要通过，回放出现重复副作用，迁移后增量数据和回退尚无证据。
- [x] 编写测试证据盘点、按需差分/彩排/影子验证、范围判断及已有授权处理规则。
- [x] 独立试用检查：运行时长不代替覆盖，未知不写通过，不把评估授权扩展成生产执行；无迁移的项目不强制迁移步骤。
- [x] 验证并提交该技能。

## Task 5：上线稳定技能

**Files:** `skills/rewrite-stabilization/SKILL.md`、`agents/openai.yaml`、`references/observation-record.md`。

**Interfaces:** 接受运行数据、已知问题或观察目标与基线；输出有范围的问题处置、修复/回归证据、性能比较和剩余观察项。

- [x] 基线场景：延迟表面下降，但负载下降且错误率增加，尚未配置持续监控。
- [x] 编写可比较基线、针对性修复、回归验证和观察退出条件。
- [x] 独立试用检查：不宣称无证据的改善，不虚称后台持续监控，不扩大为全系统重写。
- [x] 验证并提交该技能。
