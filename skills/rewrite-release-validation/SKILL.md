# 重写发布验证

独立接受候选版本、目标环境、验收标准及现有测试和运行记录；确认本次任务授权到评估、隔离验证、分批切换或生产切换的哪一步。先按已知要求写明适用范围、验收、停止与回退条件。已有明确依据和授权直接沿用；只就缺少且影响判断的业务决定请求确认。技能不扩展执行权限。

先盘点已有的 E2E、接口契约、业务规则、数据对账及其他适用检查。对可能影响外部系统的测试，执行前核对授权范围、副作用与隔离条件；隔离未知时先不执行这些测试，再运行可安全执行的适用检查。保留旧测试中的业务断言；“确认调整”按获批的新标准验证，“确认保留”按兼容标准验证，“尚待确认”不臆定预期。将功能到 E2E 的**对应关系、实际覆盖、运行结果**分别核对，绑定候选版本、环境、数据范围和运行编号。失败要区分候选缺陷、测试不稳定与环境问题，并写证据和未决原因；反复重试后的偶然通过不能抹去失败。

沿用输入材料已有的行为、功能和问题编号；没有编号的新结论建立稳定编号，关联证据、版本及三类行为标记。后续复验和交接沿用编号，不以文字描述相近代替同一结论的追踪，也不要求先执行其他技能。

依据实际变化及风险选择增量验证，例如同条件新旧差分、迁移彩排、代表性负载、影子验证或分批切换。迁移与影子运行仅在适用时检查；涉及它们时核对增量变化、状态、外部副作用、写入隔离及可执行的数据和程序回退。异常副作用或隔离未知时，先停止可能产生外部影响的测试，查清影响后再决定验证方式。观察时长由行为周期与覆盖需求决定，时间经过本身不是覆盖证据。

用[发布验证记录模板](references/release-record.md)交付**满足条件／不满足条件／证据不足**之一，注明判断范围、证据、缺口及可做的下一步。关键验收仍取决于“尚待确认”行为，或实际执行与回退证据不足时，不得声明相关范围满足条件。生产切换仅在本次授权涵盖且发布条件满足时执行；否则止于已授权的评估或验证，记录待补决策与证据。
