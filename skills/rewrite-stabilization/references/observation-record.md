# 观察与处置记录模板

按实际范围取用栏目；未知项写“待确认”，未执行项写“未运行”，不要把计划写成结果。每条结论附来源或可定位的证据。沿用已有行为/问题 ID；新增结论无 ID 时建立稳定编号，关联证据及其版本，在修复、复验和交接记录中继续使用。编号格式可沿用项目约定。

## 观察范围与依据

| 项目 | 记录 |
| --- | --- |
| 问题或观察目标、业务影响 |  |
| 候选版本 / 旧基线、环境与部署范围 |  |
| 指标目标、定义、约定来源 |  |
| 行为分类 | 确认保留 / 确认调整 / 尚待确认；依据、受影响功能与待决问题 |
| 数据来源及限制 | 日志、监控、运行记录、测试等；访问范围与缺口 |

## 基线与差异

| 指标或行为 | 旧版值及证据 | 新版值及证据 | 可比条件 | 结论与限制 |
| --- | --- | --- | --- | --- |
| 如错误率、p95、吞吐、重试结果 |  |  | 时间窗、负载、请求构成、数据集、环境、样本量、统计口径 |  |

负载、流量组成或时段不一致时，分别陈述观察值和混杂因素；不要直接归因于重写。缺少旧版样本或运行权限时，列出所需样本、采集来源、隔离复现步骤与可比条件。

## 有界处置与验证

| 稳定问题/结论 ID、关联行为 ID 与优先级 | 定位证据 | 已采取动作或拟议动作 | 范围边界 | 前后证据 | 验证结果 |
| --- | --- | --- | --- | --- | --- |
|  | 请求类别、错误样本、路径与影响 | 记录版本、改动、执行者；未实施则标记“拟议” | 关联路径和边界，避免无依据扩展 | 两侧版本、环境、负载、样本量、指标 | 单元、集成、E2E；命令或步骤、运行编号及结果 |

若涉及行为变化，记录确认依据；保留既有有效业务断言。另列功能到 E2E 的对应、实际覆盖、候选版本是否运行通过，三者不可互代。未运行的测试说明原因和剩余风险。

## 剩余观察与退出

| 观察项 / 已知风险 | 指标与采集来源 | 责任与实际运行机制 | 触发条件及处置 | 退出条件 |
| --- | --- | --- | --- | --- |
|  |  | 已存在的监控、明确调度，或“尚未配置” | 依项目 SLO、风险或已有决定填写；未知则待确认 | 与目标、错误分布、关键行为及可比验证相连 |

写明当前状态：一次性分析、已安排未来采集，或已核实持续监控运行；仅有建议时不得写“持续监控中”。完成条件是本次范围有处置结果或明确证据缺口，指标可比较或有可执行采集方案，风险及剩余观察项清楚。
