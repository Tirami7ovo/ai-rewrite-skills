# 审计报告模板

按实际范围删去不适用字段；没有材料的字段写“未提供”或“未验证”，不要填入推测的结果。

## 审计边界与证据

- 候选版本 / 旧版本标识、审查模块、环境与时间：
- 预期行为依据：规格、批准决定、接口与状态规则，附具体定位。
- 实现依据：新旧代码、测试、变更记录，附版本和定位。
- 运行依据：输入、环境、版本、命令或运行编号、输出；注明是否同条件。历史测试通过不自动适用于候选版本。
- 未获得的关键证据与影响：

## 一、行为差异报告

| 编号 / 行为 | 分类：确认保留 / 确认调整 / 尚待确认 | 依据与预期 | 新旧观察及证据等级 | 判断、影响与处置 | 验证方式或限制 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

“确认调整”以批准的新验收标准判断；一致性检查不把获批变化记为回归。“尚待确认”写清互相冲突或缺失的依据、需要谁决定什么，不做通过结论。区分测试用例与功能的对应关系、实际覆盖、在候选版本上的运行通过。

## 二、缺陷与安全报告

| 编号 / 位置 | 证据等级及事实 | 潜在或已证实的影响 | 新旧版本影响范围 | 验证方法与限制 | 建议处置 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

证据等级口径：

- **已复现**：在明确版本、环境、输入与步骤下观察到结果；附可核查记录。若只复现代码行为，仍需区分实际暴露或业务影响是否已证实。
- **静态发现**：代码、配置或数据流可定位，足以指出具体危险行为；执行频率、可达性或暴露范围可能仍未知。
- **待验证推测**：线索不足以确认缺陷或影响；列出下一步取证，不写成已发生事件。

沿袭旧版的缺陷仍列在本节，并标注“共同遗留”；旧版相同不能作为安全或正确的证明。对敏感数据、外部调用与状态变更，分别核实触发路径、权限或隔离、影响范围，避免把代码线索扩大为已证实的外泄或损失。

## 修复与独立复审记录

- 修复授权、实施者、变更版本与定位：
- 复审者或新上下文、分配模块及其取得的原始依据：
- 复审范围：原发现、邻近路径、边界、错误处理、副作用与相关旧断言。
- 复审证据：代码检查、测试与实际运行分别记录版本、环境、输入和结果；未运行项目明示。
- 逐项结论：已解决 / 仍存在 / 待验证，附依据；剩余风险、决策人及后续验证。

审计阶段默认只报告发现。有修复授权才记录实施与复审；复审不照抄实施者自述，也不以审查者人数作为通过证据。
