# 旧系统规格蒸馏

接受提取范围和现有材料，产出有证据支撑的规格包：PRD、功能清单、外部接口约定、状态与恢复规则、功能到 E2E 的对应表。五项可以按项目格式分别保存或组合组织，但都须独立可辨。先记录范围、材料及已知版本；只对已取得的材料和范围声称完成提取。

## 提取与判定

1. 对协议/文档、旧代码、测试、运行记录及已认可的新要求分别提取候选结论。条件允许时，安排两个独立上下文先各自提取，再由独立审查者对照原始材料核对；先独立形成结果，再比较，避免早期结论影响后续提取。独立审查不能替代来源证据。
2. 为共享结论和证据建立稳定编号，并记录结论关联的 PRD 需求、功能、接口、状态规则及 E2E 的独立编号。每条结论记录来源的已知版本、可定位位置，以及材料对本次重写的适用范围/有效性及其依据；缺失版本或执行记录如实写明。材料不支持的目标、指标、接口语义或运行结果不得补全。
3. 区分“确认保留”“确认调整”“尚待确认”。有明确适用于本次重写的用户决定或已认可需求、兼容要求支持目标时，按其内容判定，不因旧材料存在矛盾而重复索要确认。目标决定或材料适用性未知时，并列保存文档、实现、测试的证据，标为尚待确认，写明问题与影响范围；不能仅凭文档已签署、版本较新或模型认为更合理便选定目标。疑似缺陷本身不授权改变兼容行为。保留业务验收语义，不把内部实现方式当成必须保留的要求。
4. 将共享结论分别映射到五项交付物。功能与规则到 E2E 允许多对多；分别标明用例定义、覆盖判断、实际执行结果。测试中的既有业务断言要留痕，列出用例不等于覆盖或通过。没有 E2E 时标出缺口和可补场景，不编造用例，也不自动扩大到补建测试。
5. 检查每项交付物、每条结论的来源与冲突，反查行为结论到 PRD、功能、接口、状态及 E2E 的编号关联，并核对待确认清单。交接时说明哪些范围可用于实现，哪些仍依赖决定或取证；待确认事项存在不妨碍已取证范围交付。

需要字段和可直接改用的表格时，读取 [交付物与记录模板](references/deliverables.md)。模板字段是核对要点，可适配项目已有格式，不要求固定文档工具或文件名。
